# Accessibility requirements (WCAG 2.2 AA)

These came out of an audit of the earlier prototype. Each one is a requirement.

## Structure
- `<html lang="en">`. A skip link ("Skip to content") as the first focusable element, pointing at `<main id="main">`.
- One `h1`. Each § section is a `<section aria-labelledby>` with an `h2`. No skipped heading levels (the footer "Revision history" is an `h2`).
- The header `<nav aria-label="Sections">` stays visible on mobile and scrolls horizontally. It is never hidden.

## Color and contrast
- Use only the tokens in `design/tokens.css`. Check every text/background pair in both themes, including hover states.
- Never use white text on `--rubric`. Use `--paper` on `--ink` or `--rubric`.
- The focus ring is a 2px `--rubric` outline with a 3px offset on every interactive element. Never set `outline: none` without a replacement.

## Interaction
- Theme toggle: a `<button>` with `aria-pressed`. Its label says what it will do ("Switch to dark theme"). An inline `<head>` script applies the saved theme before paint.
- Copy email: a `role="status"` live region announces "Email copied". The email itself is also a `mailto:` link.
- FAQ: native `<details>/<summary>`. No custom tabs.
- Redaction bars: `tabindex="0"`, `role="img"`, `aria-label="Client name withheld under NDA"`, with the tooltip shown on `:focus` as well as `:hover`.
- Touch targets are at least 44px (buttons, toggle, nav links, summaries).
- No content moves or loops for more than 5 seconds. The site has no auto-playing motion.

## Images and figures
- Plate I: `alt="Abdelrhman Fikri"`. Plate II is decorative: `alt=""`.
- Every figure SVG has `role="img"` and an `aria-label` describing the flow in one sentence, plus a visible `<figcaption>`.
- No SVG text renders smaller than 12px on mobile. Either use a vertical variant below 640px, or make the scroll container focusable (`tabindex="0"`, `role="region"`, `aria-label="Figure N, scrollable"`).

## Links
- No `href="#"` and no links to the section the user is already in. A post-mortem card links only from its `h3` (`<a href="/work/slug">`); a pseudo-element can make the whole card clickable.
- Each external link names its destination ("LinkedIn profile"). The CV link says "(PDF)".

## CI gate
- Run `pa11y-ci` (or `@axe-core/cli`) and Lighthouse CI on the built site in GitHub Actions. A failure blocks the merge.
- Test by hand at 320px width, at 200% zoom, keyboard-only, and in both themes.
