Work, written as post-mortems

PM-01Logistics integrationClient

Self-healing redeploys for high-load incidents

Summary
The same high-load incident kept coming back, and each time someone had to restart the service by hand.
What I did
I connected CloudWatch alarms through SNS to a listener that triggers a Jenkins redeploy. I later applied the same loop to a logistics client's integration.
Result
Mean time to recovery down 40%. No manual restarts for that incident type.
Stack
CloudWatch, SNS, Jenkins, Python
PM-02Security incidentAccount

Responding to a compromised AWS account

Summary
Unexpected cost anomalies showed that a company AWS account had been compromised.
What I did
I rebuilt the timeline from the cost data, removed rogue IAM users, closed exposed ports, stopped SES and domain abuse, and cleared the domain's malware warning. Then I added MFA, least-privilege IAM and budget alarms.
Result
Account recovered, with guardrails in place to prevent a repeat.
Stack
IAM, SES, Route 53, AWS Budgets
PM-03Regulated industry, document processingClient

Claude on Amazon Bedrock for a regulated client

Summary
A document-processing platform needed LLM features without breaking the client's data-retention and access rules.
What I did
I deployed Claude models on Amazon Bedrock with Zero Data Retention enforced, least-privilege IAM, and CloudWatch alarms on cost and usage.
Result
Met the client's data-retention and access-control requirements.
Stack
Amazon Bedrock, IAM, CloudWatch
PM-0420+ client and internal products

One release setup for 15+ repositories

Summary
Releases across many client and internal products involved manual steps, and every environment was set up by hand.
What I did
I moved 15+ repositories onto GitHub Actions and Jenkins pipelines with PR-gated Dev, Staging and Prod environments. Terraform and Ansible now handle environment setup.
Result
70% less manual environment setup. Releases no longer need manual steps.
Stack
GitHub Actions, Jenkins, Terraform, Ansible, Docker

Freelance

I take on DevOps work for startups and small teams alongside my full-time role.

CI/CD and releases
Pipelines that test, scan, build and deploy web apps, plus App Store and Google Play publishing with signing and versioning.
AWS setup and migration
EC2, ECS, S3 and CloudFront, RDS and Route 53, written in Terraform so you can rebuild it.
Monitoring, backups and cost
CloudWatch or Grafana alerts, automated backups with RTO and RPO targets, and a review of what you're paying for.
Security and AI infrastructure
IAM and MFA cleanup, scanning in CI, and Bedrock deployments with data-retention controls.

How a project runs

  1. Review. I look at your current setup, costs and risks, and we agree what to fix first.
  2. Build. Pipelines, infrastructure as code, and separate Dev, Staging and Prod environments.
  3. Release. Deploys with a rollback plan, including mobile store releases if you need them.
  4. Hand over. Alerts, runbooks and architecture docs, so your team can run it without me.
FitBest for teams with live users and no dedicated DevOps engineer yet.
